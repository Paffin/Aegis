# aegis-mcp: фильтр для серверов MCP

Gateway видит то, что агент отправляет модели. Серверы MCP (трекер задач, база данных, репозиторий, чат) агент вызывает сам, и gateway видит этот трафик только как текст вызова и результата. `aegis-mcp` встаёт между агентом и сервером MCP и делает то, чего gateway сделать не может:

- **скрывает** инструменты, которых нет в белом списке, из `tools/list` и отклоняет их вызов (`M-01`);
- **проверяет аргументы** вызова: шаблон, список значений, длина, обязательность; для SQL-инструментов пропускает только чтение (`M-02`, `M-03`);
- **убирает поля** из результатов раньше, чем их увидит агент, а через него и модель (`M-10`). Это необратимое удаление;
- **помечает** сервер как недоверенный (содержимое пишут не вы) и как выходящий наружу (чат, публичный репозиторий): gateway применяет к его инструментам правило трёх условий.

Псевдонимизация остаётся за gateway: `aegis-mcp` не маскирует значения, он ограничивает, что сервер вообще может сделать и вернуть.

## Конфигурация

Строгий YAML: неизвестное поле, пустой список или неверное значение — ошибка при запуске.

```yaml
version: 1
audit_path: /var/log/aegis/mcp-audit.jsonl   # решения без значений; без пути — в stderr
servers:
  tracker:
    trust: untrusted        # содержимое пишут не вы
    egress: true            # вызовы выходят за периметр
    url: https://mcp.example.com/mcp          # только для Streamable HTTP
    headers_env: { Authorization: TRACKER_MCP_TOKEN }   # заголовок -> переменная окружения
    tools:
      allow: [get_issue, list_*, create_issue]   # обязательно; ["*"] разрешает всё осознанно
      args:
        create_issue:
          unknown: deny                          # аргументы без правила отклоняются
          repo:   { pattern: 'acme/[a-z-]+', max_length: 40, required: true }
          labels: { enum: [bug, feature] }       # для массива проверяется каждый элемент
          title:  { forbid_pattern: '(?i)password|secret' }
        get_issue:
          filter.project: { enum: [WEB, API] }   # точка — вложенный аргумент
      sql_read_only:
        query: [sql]                             # инструмент -> аргументы с SQL
    results:
      drop_fields: [email, ssn]   # ключи JSON на любой глубине и колонки CSV/TSV
      max_bytes: 20000            # длиннее — обрезается
```

`aegis-mcp check mcp.yaml` показывает, что конфигурация разрешает.

## Подключение

**stdio** (сервер запускает клиент): оберните команду сервера. Claude Code, `.mcp.json`:

```json
{ "mcpServers": { "tracker": {
    "command": "aegis-mcp",
    "args": ["stdio", "--config", "/etc/aegis/mcp.yaml", "--server", "tracker", "--", "npx", "-y", "@acme/tracker-mcp"] } } }
```

Codex, `~/.codex/config.toml`:

```toml
[mcp_servers.tracker]
command = "aegis-mcp"
args = ["stdio", "--config", "/etc/aegis/mcp.yaml", "--server", "tracker", "--", "npx", "-y", "@acme/tracker-mcp"]
```

**Streamable HTTP**: `aegis-mcp http --config /etc/aegis/mcp.yaml --listen 127.0.0.1:9100`. Клиент обращается к `http://127.0.0.1:9100/tracker`, `aegis-mcp` пересылает запрос на `url` сервера. Учётные данные сервера берутся из переменных окружения процесса (`headers_env`), клиенту их не передают. Ответы JSON и потоки событий фильтруются одинаково. Слушайте только локальный адрес: у самого прокси аутентификации нет.

## Метки доверия и выход наружу

Gateway узнаёт об этих метках из своей политики. Команда `aegis-mcp policy-snippet mcp.yaml` печатает нужный фрагмент:

```yaml
trifecta:
  untrusted_tools: ["mcp__tracker__*"]   # результаты этих инструментов недоверенные
  egress_tools: ["mcp__tracker__*"]      # вызовы этих инструментов — как сетевые
```

Результат недоверенного инструмента в контексте взводит условие «недоверенный контент» правила трёх условий. Вызов инструмента из `egress_tools` проверяется как сетевой: секрет в нём не подставляется никогда, внутренние адреса подставляются только внутренним адресатам, а если в контексте есть приватные данные и недоверенный контент, вызов останавливается. Имена инструментов в клиентах разные (`mcp__сервер__инструмент` у Claude Code, `mcp_сервер_инструмент` у других): фрагмент содержит оба варианта.

## SQL «только чтение»

Проверка консервативная и не заменяет права базы: пользователь базы для агента должен быть только читающим. Запрос должен быть одним оператором, начинаться с `SELECT`, `WITH`, `EXPLAIN`, `SHOW`, `DESCRIBE` или `VALUES`, не содержать слов, которые пишут (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `INTO`, `COPY`, `CALL`…), блокировок строк (`FOR UPDATE`) и функций с побочным действием (`pg_sleep`, `nextval`, `load_file`). Формы, которые разные базы читают по-разному (`--x` без пробела, обратная косая черта в кавычках, долларовые кавычки, исполняемые комментарии MySQL), отклоняются, потому что отклонённый запрос можно переписать, а выполненную запись не вернуть.

## Что не делается

- Ресурсы и подсказки (`resources/*`, `prompts/*`) пропускаются без фильтрации; списки и результаты инструментов фильтруются.
- Результат, который не JSON и не таблица с заголовком, правилами `drop_fields` не затрагивается; по размеру он обрезается.
- Сообщение сервера, которое не JSON (сервер пишет журнал в stdout), не передаётся клиенту.
- Конфигурация читается при запуске; изменение требует перезапуска клиента.
