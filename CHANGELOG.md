# Журнал изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по [SemVer](https://semver.org/lang/ru/). Пока `0.x`, совместимость между версиями не гарантируется.

## [Не выпущено]

### Добавлено
- Протокол **Google Gemini**: `generateContent`, `streamGenerateContent` (SSE и JSON-массив), `countTokens`, `embedContent`; `camelCase` и `snake_case`; подписи рассуждений не изменяются.
- Протоколы **OpenAI Completions** (автодополнение, fill-in-the-middle) и **OpenAI Embeddings** (индексация кода).
- Провайдеры независимы и необязательны: Anthropic, OpenAI-совместимый, Gemini. Способы авторизации `x-api-key`, `bearer`, `api-key` (Azure), `x-goog-api-key`, `none` (локальные модели); `openai_api_prefix` для вендоров без `/v1` (Zhipu, Volcengine, Qianfan).
- Виртуальный ключ принимается из `x-api-key`, `Authorization`, `api-key`, `x-goog-api-key` и `?key=`; ключ из запроса провайдеру не передаётся.
- Китайские модели: отказ встроенного поиска (`enable_search`, `$web_search`, `web_search`, `retrieval`), параллельные вызовы без `index`, `reasoning_content`.
- `aegis scan`: что будет замаскировано в файлах, без вывода значений; `--mask`, `--json`, `--fail-on-findings`.
- `scripts/demo.sh`, каталог `examples/`, `docs/PROVIDERS.md`, переписанный `docs/CLIENTS.md`.

- Набор эксфильтрации (QA-08): более 1300 сценариев, `tests/exfil.rs`. Property-тесты ядра (INV-1, INV-3, INV-4, устойчивость) и фаззинг запросов и потоков (`tests/fuzz.rs`, proptest; `PROPTEST_CASES=40000` для долгого прогона).

- `aegis-bench load`: нагрузочный стенд по настоящему HTTP (добавка ко времени до первого байта, поток запросов, одновременные потоки); в CI.
- В CI: сборка образа, запуск его read-only без привилегий, `helm lint` и `helm template`.

- `scripts/client-claude-files.sh`: сценарий из концепции с настоящим Claude Code (секрет возвращается в файл-источник, в другой файл не попадает).
- `scripts/clients.sh`: настоящие Claude Code, Codex CLI, Qwen Code, Gemini CLI, OpenCode, Aider, Continue, Cline, Hermes Agent, OpenClaw, Crush, Kilo Code, Pi, Goose, Copilot CLI и Mistral Vibe против Aegis и подставного провайдера (`mock_anthropic.py`, `mock_openai.py`, `mock_gemini.py`); в CI.
- Имена инструментов других агентов (`exec_command` у Codex, `run_shell_command`, `write_file`, `web_fetch`… у Gemini CLI и Qwen Code, `bash`, `edit`… у OpenCode, `Fetch`, `List` у Continue, `run_commands` со списком команд, `read_files`, `submit_and_exit` у Cline).

- **Этап 2:** `aegis-guard` — хук клиента на машине разработчика (`AGG-01`, `AGG-02`, `AGG-07`): закрытые файлы, опасные команды, список узлов, пути приводятся к виду файловой системы; проверен настоящим Claude Code (`scripts/client-claude-guard.sh`); `aegis-guard settings` печатает настройки клиента. Документ: [docs/GUARD.md](docs/GUARD.md).
- Источники ключей (`CFG-05`, `CFG-07`): `ИМЯ_COMMAND` рядом с `ИМЯ` и `ИМЯ_FILE` (Vault, KMS, `pkcs11-tool`: команда без оболочки, таймаут 15 с, ошибки не в журнал); `aegis-gateway check` отказывает, если файл ключа доступен другим. PKCS#11 напрямую не сделан.
- Доверие между охранником и gateway (`AGG-03`, `AGG-05`): `aegis-guard enroll|token|credential`, подписанный токен устройства (Ed25519 вместо HMAC из спецификации: на gateway только открытые ключи), раздел `guard` в конфигурации, подстановка персональных данных в локальные команды при действительном токене и правило `G-05` на машине (почта, телефон, паспорт, СНИЛС, ИНН, карта; 10 мс). Проверено настоящим Claude Code: ключ с токеном через `apiKeyHelper` (`scripts/client-claude-agg.sh`).
- Измерение индекса закрытого кода (`aegis-bench code`, `QA-10`, шаг в CI): фрагменты по 40 строк, полнота среди оцениваемых 97–100% на четырёх репозиториях из пяти, ложные совпадения 0–0,03%. Измерение нашло, что таблицы чисел совпадают у любых двух репозиториев (1–2% ложных): добавлено условие «не меньше 12 разных идентификаторов в блоке». Пороги по умолчанию теперь 0,9 и 50 токенов.
- Таблица форматов вокруг пароля (`crates/aegis-core/tests/formats.rs`, 70+ обёрток: просмотр с номерами строк, `grep -n`, `diff`, Markdown, JSON внутри JSON, HTML-кавычки, BOM, XML, `os.environ["…"]`, строки подключения, Docker, YAML, TOML, INI и другие). Нашла 11 пропусков, все исправлены; ложные срабатывания те же (2,76 на 10 тыс. строк).
- Маршрутизация по классификации (`RTE-03`…`RTE-05`): действие `route:<имя>` в `code_index.actions` отправляет запрос с закрытым кодом на внутренний маршрут (`reroute_only`, `model`, `context_tokens`); разговор закрепляется за маршрутом на 8 часов; уведомление в начале ответа и `route=` в `X-Aegis-Summary`; несовместимый или отсутствующий маршрут — отказ 403, а не возврат к внешнему провайдеру.
- **Настоящий провайдер** (`scripts/client-real.sh`, `scripts/real_tap.py`): 15 клиентов (все, кроме Gemini CLI) прошли против OpenRouter с настоящими моделями (`gpt-4o-mini`, `gpt-5-mini`, `claude-haiku-4.5`) в двух сценариях: команда с выдуманным хостом и паролем, правка файла с паролем. Между Aegis и провайдером стоит прозрачный прокси, который записывает, что провайдер получил. Первый же прогон нашёл две дыры в детекторе паролей, которых не видели ни тесты, ни подставной провайдер: пароль в строке с номером (`2|DB_PASSWORD=…`, так читает файлы Hermes, Crush) и пароль в JSON-строке с `\n` вместо перевода строки (Vibe) уходили провайдеру открытым текстом. Исправлено, закреплено тестами, доля ложных срабатываний не изменилась (2,76 на 10 тыс. строк). Проверено также: зашифрованные элементы рассуждения Codex (`reasoning.encrypted_content`) проходят туда и обратно, провайдер отвечает 200.
- **Новые клиенты** (`scripts/client-{hermes,openclaw,crush,kilo,pi,goose,copilot,vibe}.sh`, общая часть в `scripts/lib-client.sh`): Hermes Agent, OpenClaw, Crush, Kilo Code, Pi, Goose, GitHub Copilot CLI и Mistral Vibe проверены настоящими бинарниками. В классификацию инструментов добавлены `terminal`, `exec`, `file_write`, `create`, `view`, `browser_navigate`, `web_extract`, `delegate_task`, `sessions_spawn`, `subagents`. Goose отбрасывал текст после вызова инструмента: объяснение отказа в потоке Chat теперь стоит перед оставшимися вызовами.
- Остатки разбора: `max_connections_per_ip`, `count_tokens` идёт по маршруту и с псевдонимами моделей, разрезание адреса проверено в потоках Chat, Responses и Gemini (все позиции разреза).
- **Внутренний разбор безопасности** (отдельный проверяющий, не внешний пентест): 7 серьёзных и 6 средних находок, все воспроизведены и закрыты тестами (`tests/hardening.rs`, `tests/review_tools.rs`):
  - потоки: значение в URL, разрезанном границей кусков потока, оставалось подставленным (контекст прежних кусков теперь учитывается);
  - оболочка: `sed … e`, `awk system (…)`, `rg --pre`, `sort --compress-program`, `git -C`, интерпретаторы с `-Bc`/`-le` считались локальными (теперь разбор опций, а не подстрок; `git add/commit` — выполнение кода проекта);
  - адреса: `host\@внутренний`, табуляция и перевод строки внутри адреса, процентное кодирование хоста (теперь «двусмысленный адрес» никогда не внутренний);
  - вызовы: два поля команды (`command` и `cmd`), два пути (`file_path` и `filePath`), происхождение секрета от любого инструмента, смещённый заголовок патча, `env` команды, `command` у `attempt_completion`;
  - доступ: тело запроса читалось до проверки ключа, нет таймаутов тела и заголовков, пути с `..` доходили до провайдера с ключом gateway, редиректы провайдера выполнялись с ключом, значение в имени модели попадало в аудит, откат на старый подписанный бандл, опечатка в конфигурации молча отключала защиту, пароль в объекте JSON под ключом `db_password` не находился (ключ теперь контекст).
- Индекс закрытого кода (`DET-20`, `DET-21`): `aegis index build|info|check`, отпечатки winnowing с ключом тенанта, раздел `code_index` в gateway, действия по классификации репозитория, обновление файла без перезапуска.
- Вход по токену OpenID Connect (`oidc`): RS256 и ES256 по ключам издателя, группы из утверждений работают в маршрутах (`IAM-04`, `T2-13`).
- **Этап 2, начало:** `aegis-mcp` — фильтр между агентом и серверами MCP (stdio и Streamable HTTP): белый список инструментов, проверка аргументов, SQL только чтение, удаление полей из результатов, фрагмент политики для меток доверия и выхода наружу (`MCP-01`…`MCP-05`); в политике gateway `trifecta.egress_tools` и шаблоны в `untrusted_tools`. Документ: [docs/MCP.md](docs/MCP.md).
- Политика решает судьбу вложений и эмбеддингов целиком (`defaults.attachments`, `defaults.embeddings`: `block_request`) (`POL-05`).
- `scripts/docs-check.sh`: документы и конфигурации, которых требует спецификация (`CMP-*`, `EGR-*`, `NFR-05`, `NFR-08`, `QA-09`), проверяются в CI; в документах появились ротация аудита, настройки у провайдера, масштабирование и работа без интернета.
- Маршруты по имени модели и группе ключа (`routes`): свой провайдер, свои учётные данные и своё имя для правил политики (`RTE-01`).
- Трассировки OpenTelemetry по стадиям без тел запросов (`otlp_endpoint`, `traceparent`, `OBS-03`).
- TLS и mTLS на основном порту (`tls`), перечитывание сертификатов без перезапуска, закрепление УЦ провайдера (`upstream_ca_file`), поддержка в Helm-чарте (`config.tls`) и в `aegis-gateway check` (`SEC-05`).
- Проверка ответа модели (`RSP-06`, `RSP-10`): секрет, который модель написала сама в аргументах вызова (по умолчанию отказ, в записываемом файле — запись в аудит), опасные команды (`curl | sh`, `rm -rf /`, `authorized_keys`, отключение песочницы), свои шаблоны; раздел `response` политики.
- Цепочка поставки (`SEC-09`): `deny.toml`, `scripts/supply-chain.sh`, задача `supply-chain` в CI (cargo-deny, cargo-audit, SBOM CycloneDX), выпуск по тегу с подписью образа (cosign), образом для amd64 и arm64 и контрольными суммами.
- Сбой детектора (`DET-09`): блок, который не успели проверить за `detect_budget_ms` или проверка которого упала, удаляется, а не пропускается; кэш обнаружения ограничен по памяти (`DET-03`, `detect_cache_mb`).
- `model_aliases`: псевдонимы моделей (`RTE-02`).
- `aegis-gateway check <config>`: проверка конфигурации, ключей, провайдеров, бандла, аудита и портов до запуска; значений не печатает; код выхода 0/1.
- Защита от перегрузки и зависшего провайдера: `max_concurrent_requests` (503 с `Retry-After` до чтения тела), `upstream_connect_timeout_secs`, `upstream_read_timeout_secs` (502).

### Исправлено
- Строка запроса (`/v1/messages?beta=true` у Claude Code) терялась по дороге к провайдеру.
- Конфигурация только с `openai_base_url` без `openai_api_prefix` не создавала провайдера (находка Codex).
- Пояснение об отказе вызова приклеивалось к хосту в потоке (`prod-db01.corp.local[Aegis]`), и хост не распознавался при возврате истории; теперь оно начинается с новой строки, а хост перед `[Aegis` распознаётся.
- Значение в URL markdown-картинки, ссылки, `<img>` или автоссылки на чужой адрес подставлялось в текст ответа и уходило при отображении (RST-11).
- Не находился пароль в незакрытой кавычке и фраза-пароль с пробелами; пароли в командной строке (`curl -u`, `sshpass -p`, `redis-cli -a`, `mysql -p`).
- Маркер Aegis после ключевого слова принимался за значение; хост после `@` и пользователь с базой в строке подключения с маркером вместо пароля не находились в истории.
- Блоки `thinking`, `reasoning` с лишними полями проходили без проверки; теперь неприкосновенны только запечатанные поля.

### Изменено
- `upstream_base_url` → `anthropic_base_url` (прежнее имя читается), `AEGIS_PROVIDER_KEY` → `AEGIS_ANTHROPIC_KEY` (прежнее имя читается). Хотя бы один провайдер обязателен.
- Сжатые тела запросов отклоняются (415): их нельзя проверить.

## [0.1.0] — первая рабочая версия

### Добавлено
- Ядро: обнаружение (секреты, инфраструктура, ПДн, словари, свои детекторы), псевдонимы без хранилища (HMAC, Crypto-PAn для IPv4, 3fff::/20 для IPv6), подстановка по месту назначения, shell-лексер, правило трёх условий.
- Gateway: Anthropic Messages, OpenAI Chat и Responses (без состояния), потоки с окном удержания, подписанный бандл политики (Ed25519) с горячей заменой, аудит без значений, метрики Prometheus, fail-closed, усиление процесса.
- Строгий разбор JSON и проверка всех строк запроса (защита от расхождения разборщиков и полей вне схемы).
- CLI `aegis`: ключи, бандлы, тесты политики, виртуальные ключи, отчёты.
- `aegis-bench`: ложные срабатывания, полнота, задержка; гейты в CI.
- Документация: концепция, спецификация, план, администрирование, модель угроз, обработка данных; Dockerfile, Helm-чарт, systemd, egress.
