# Aegis — руководство администратора

Документ описывает то, что реализовано в репозитории сейчас. Статус по плану работ — в [STATUS.md](STATUS.md).

## 1. Состав

| Бинарник | Назначение |
|---|---|
| `aegis-gateway` | Прокси между клиентами и провайдерами: Anthropic Messages, OpenAI (Chat Completions, Responses без состояния, Completions, Embeddings), Google Gemini |
| `aegis` | Администрирование: ключи подписи, сборка и проверка бандла политики, тесты политики, виртуальные ключи, отчёты по аудиту, `aegis scan` (что было бы замаскировано в ваших файлах) |
| `aegis-guard` | Проверка вызова инструмента на машине разработчика (хук клиента): закрытые файлы, опасные команды, список узлов ([GUARD.md](GUARD.md)). Этап 2 |
| `aegis-mcp` | Фильтр между агентом и серверами MCP: белый список инструментов, проверка аргументов, SQL только чтение, удаление полей из результатов ([MCP.md](MCP.md)). Этап 2 |
| `aegis-bench` | Измерения: ложные срабатывания, полнота, задержка преобразования, нагрузка по HTTP (`load`) |

## 2. Запуск

```
aegis-gateway /etc/aegis/gateway.json
```

Секреты берутся не из конфигурации, а из окружения (`ИМЯ`), из файла (`ИМЯ_FILE`) или из вывода программы (`ИМЯ_COMMAND`); если заданы несколько, порядок такой: файл, команда, значение. Ключи `K_t` и `K_audit` могут также лежать в HSM (`ИМЯ_PKCS11`, ниже); это четвёртый источник, и вместе с остальными он не задаётся:

| Переменная | Назначение |
|---|---|
| `AEGIS_K_TENANT` | Ключ тенанта `K_t`, не короче 16 байт. Из него считаются псевдонимы |
| `AEGIS_K_AUDIT` | Ключ аудита, не короче 16 байт. Должен отличаться от `K_t` |
| `AEGIS_ANTHROPIC_KEY` | Ключ провайдера Anthropic (прежнее имя `AEGIS_PROVIDER_KEY` тоже работает). Нужен, если задан `anthropic_base_url` |
| `AEGIS_OPENAI_KEY` | Ключ OpenAI-совместимого провайдера. Нужен, если задан `openai_base_url` и `openai_auth` не `none` |
| `AEGIS_GEMINI_KEY` | Ключ Gemini. Нужен, если задан `gemini_base_url` |

**Источники ключей** (`CFG-05`, `CFG-07`). Файл (`ИМЯ_FILE`) должен иметь права 0400 или 0600: `aegis-gateway check` отказывает, если ключ читают другие. Файл допустим для пилота и изолированных контуров без HSM; для промышленной эксплуатации ключ лучше получать из хранилища командой:

```
AEGIS_K_TENANT_COMMAND="vault kv get -field=value secret/aegis/tenant"
AEGIS_K_AUDIT_COMMAND="aws kms decrypt --ciphertext-blob fileb:///etc/aegis/audit.enc --output text --query Plaintext"   # обернуть в base64 -d по необходимости
AEGIS_K_TENANT_COMMAND="pkcs11-tool --module /usr/lib/softhsm/libsofthsm2.so --token-label aegis --login --pin env:HSM_PIN --read-object --type data --label k_t"
```

Команда запускается один раз при старте, **без оболочки** (кавычки группируют слова, `$`, `` ` `` и `~` не раскрываются), с таймаутом 15 с; ключ — её стандартный вывод без хвостовых пробелов и переводов строки (до 4096 байт), стандартный вывод ошибок отбрасывается и в журнал не попадает. Ненулевой код выхода, пустой вывод или таймаут — ключа нет, процесс не стартует. Примеры приведены для иллюстрации: синтаксис клиента вашего хранилища проверьте сами. **Ограничение:** так HSM лишь хранит ключ, а не считает: ключ читается один раз и дальше живёт в памяти процесса (как при файле). Чтобы ключ не покидал HSM, используйте `ИМЯ_PKCS11`.

**Ключи в HSM по PKCS#11** (`CFG-07`). HMAC считает токен (`CKM_SHA256_HMAC`, ключ `CKK_GENERIC_SECRET` или `CKK_SHA256_HMAC`, `CKA_EXTRACTABLE=false`, `CKA_SENSITIVE=true`), байты ключа в память Aegis не попадают: процесс передаёт данные токену и получает 32 байта. Ключ описывается переменной `ИМЯ_PKCS11`, PIN берётся отдельно:

```
AEGIS_K_TENANT_PKCS11="module=/usr/lib/softhsm/libsofthsm2.so;token=aegis;label=k_t"
AEGIS_K_AUDIT_PKCS11="module=/usr/lib/softhsm/libsofthsm2.so;token=aegis;label=k_audit"
AEGIS_HSM_PIN_FILE=/etc/aegis/hsm-pin        # или AEGIS_HSM_PIN, или AEGIS_HSM_PIN_COMMAND
```

| Параметр | Значение |
|---|---|
| `module` | Библиотека PKCS#11 (обязательно) |
| `token` или `slot` | Метка токена (лучше: номер слота меняется при переподключении) или номер слота; нужно ровно одно из двух |
| `label` | `CKA_LABEL` ключа (обязательно); `id` — `CKA_ID` в hex, если метка не единственная |
| `sessions` | Сеансов с токеном одновременно (4; 1…32) |
| `timeout_ms` | Сколько запрос ждёт свободный сеанс (5000; 100…120000) |
| `memo` | Сколько последних результатов держать в памяти (65536; 0 выключает) |
| `pin_var` | Имя семейства переменных с PIN (`AEGIS_HSM_PIN`), если у ключей разные токены |

PIN в описание ключа не входит и в журнал, `check` и сообщения об ошибках не попадает (описание с лишним параметром `pin=` отвергается, значение не повторяется). Файл PIN проверяется на права так же, как файл ключа. Если для одного ключа заданы `ИМЯ_PKCS11` и любой из `ИМЯ`, `ИМЯ_FILE`, `ИМЯ_COMMAND`, процесс не стартует: ключ, «перенесённый» в HSM, не должен остаться на диске по недосмотру. `K_t` и `K_audit` не могут указывать на один объект в токене.

*Создание ключа.* Лучше всего генерировать его внутри токена: тогда копии нет нигде.

```
aegis hsm init AEGIS_K_TENANT          # токен сам генерирует 32 байта; --bytes 48 для другой длины
aegis hsm init AEGIS_K_AUDIT
aegis hsm check                        # открывает ключи как gateway и замеряет HMAC; PIN и ключ не печатает
```

`aegis hsm init` берёт описание из `ИМЯ_PKCS11` (или `--spec "module=…;token=…;label=…"`), создаёт объект с `CKA_TOKEN`, `CKA_PRIVATE`, `CKA_SENSITIVE=true`, `CKA_EXTRACTABLE=false`, `CKA_SIGN=true`, читает атрибуты обратно (токен мог молча проигнорировать запрошенное: тогда объект удаляется и команда падает) и отказывается заменять существующий ключ: замена изменила бы все псевдонимы и сделала бы индекс закрытого кода непригодным. **Перенос действующего ключа:** `aegis hsm init AEGIS_K_TENANT --import` один раз читает текущие байты (`ИМЯ`, `ИМЯ_FILE`, `ИМЯ_COMMAND`) и кладёт их в токен как неизвлекаемые; псевдонимы и индекс остаются прежними. После этого удалите старый файл или команду и задайте `ИМЯ_PKCS11`. Токен с PIN создают средства самого HSM, например SoftHSM:

```
softhsm2-util --init-token --free --label aegis --so-pin "$SO_PIN" --pin "$PIN"
# то же без aegis hsm init, средствами OpenSC (атрибуты проверит `aegis hsm check` и gateway):
pkcs11-tool --module /usr/lib/softhsm/libsofthsm2.so --token-label aegis --login --pin env:PIN \
  --keygen --key-type GENERIC:32 --label k_t --sensitive --private --usage-sign
```

Команды `softhsm2-util` и `pkcs11-tool` приведены по их документации и в среде разработки не запускались (пакеты не ставятся): проверены токены kryoptic и NSS, см. [STATUS](STATUS.md). Неизвлекаемый ключ нельзя скопировать для резерва: копии делает сам HSM (кластер, резервное копирование с обёрткой ключом), иначе потеря токена меняет все псевдонимы.

*Что покрывает HSM, а что нет.* Это важно для оценки:

| Ключ и операции | Где считается |
|---|---|
| `K_t`: идентификаторы псевдонимов, соль разговора, отображение IP (Crypto-PAn: 24 HMAC на адрес IPv4 частной сети /8, до 80 на IPv6), метка разговора | В токене, по одному HMAC на операцию. Результаты (32 байта выхода, не ключ) последних `memo` вычислений держатся в памяти и ищутся по SHA-256 со случайной на процесс солью, а не по тексту значения |
| `K_audit`: хеши значений в аудите, хеш разговора | В токене |
| Индекс закрытого кода (`code_index`, `aegis index build`) | **Не целиком.** Отпечаток считается HMAC на каждую свёртку из токенов кода: миллионы на репозиторий; поход в токен за каждой занял бы часы (замеры ниже). Поэтому токен один раз при старте считает `HMAC(K_t, "aegis-code-index-v1")`, и эти 32 байта (ключ индекса, производный) лежат в памяти и считают отпечатки. Главный ключ из токена не выходит; утечка производного ключа позволяет проверять догадки по файлу индекса, но не раскрывает `K_t` и ни один псевдоним. Индекс, построенный прежним файловым ключом, остаётся годным, если в токен перенесены те же байты (`--import`) |
| Ключи провайдеров, виртуальные ключи, открытые ключи бандла | Не относится к `CFG-07`; остаются в окружении, файле или команде |

*Стоимость одного HMAC через токен.* Замерено на программных токенах (процессор этого стенда, 4 ядра): kryoptic 1.5.3, токен с PIN и базой на диске, **35 мкс** на вызов (три вызова PKCS#11: `C_SignInit`, длина, `C_Sign`); NSS softoken, **1,2 мкс** (токен в том же процессе, границы нет); HMAC в памяти, 0,27 мкс. Один IPv4 из частной сети /8 (24 HMAC): 0,9 мс на kryoptic, 0,04 мс на NSS; сто идентификаторов хостов: 3,7 мс и 0,16 мс. Это потолок для программного токена, а не оценка для вашего HSM: сетевой или аппаратный HSM отвечает дольше, обычно от долей миллисекунды до нескольких (по паспорту устройства, **здесь не измерялось**); умножьте на число операций запроса: примерно 1 на соль, 1 на каждое новое значение и 24 на каждый новый частный IPv4. При 1 мс на операцию запрос с 10 хостами и тремя адресами стоит порядка 80 мс (расчёт, не замер), повтор того же значения в разговоре и общие префиксы адресов берутся из памяти. Свой токен замерьте `aegis hsm check`, это же число печатает `aegis-gateway check`. Вызов блокирует поток, который обслуживает запрос, как и остальная обработка.

*Сбои и отказ в обслуживании (fail-closed).* Не открылся модуль, нет токена, ключа или PIN не принят: процесс не стартует, `aegis-gateway check` печатает причину (без PIN и ключа). Ключ короче 16 байт или извлекаемый (`CKA_EXTRACTABLE` не `false`, `CKA_SENSITIVE` не `true`): отказ. Во время работы: сеанс, который токен больше не знает (сброс, токен вынули и вставили, перезапуск модуля, потеря входа), выбрасывается вместе с остальными простаивающими, токен и ключ ищутся заново по метке, операция повторяется один раз; если не получилось, запрос получает **503** (`api_error`, «ключ в HSM недоступен»), к провайдеру ничего не уходит, `/readyz` отвечает 503, а в течение секунды ключ отвечает отказом сразу, не дожидаясь токена. Раз в 10 секунд (пока токен недоступен, раз в 2 секунды) ключ сам проверяет токен: вернувшийся токен подхватывается без перезапуска. PIN, который токен отклонил, **не повторяется** (токены блокируются после нескольких неудач); для этого нужен перезапуск с верным PIN. Если все сеансы заняты зависшим вызовом, остальные запросы ждут `timeout_ms` и получают 503; сам зависший вызов прервать нельзя (в PKCS#11 нет отмены).

*Пределы.* Модуль PKCS#11 — машинный код производителя, загружаемый в процесс gateway; его сбой роняет процесс (сами Aegis без `unsafe`, а библиотеку `cryptoki` и модуль мы не проверяем). Один модуль инициализируется один раз на процесс; вход в токен общий для процесса, поэтому токен, в который уже вошёл другой ключ, не перепроверяет PIN второго (оба ключа берут PIN из одного места). Смена ключа в токене на месте требует перезапуска: псевдонимы должны быть стабильны. В образе (`distroless/cc`) библиотеки модуля нет: смонтируйте модуль вместе с его зависимостями (для SoftHSM это `libsofthsm2.so` и его конфигурация) и укажите путь в `module`. Облачные KMS без PKCS#11 этим способом не подключаются; для них остаётся `ИМЯ_COMMAND` (ключ при этом в памяти процесса).

Ключи провайдеров клиентам не выдаются. Без `K_t`, `K_audit` и ключа каждого настроенного провайдера процесс не стартует. Если бандл настроен, но действительного бандла нет, процесс отвечает 503 и `readyz` не готов (fail-closed).

### Конфигурация (`gateway.json`)

| Ключ | Значение |
|---|---|
| `listen`, `admin_listen` | Адреса основного и служебного портов. Служебный порт (`/healthz`, `/readyz`, `/metrics`) не должен быть доступен клиентам |
| `anthropic_base_url` (прежнее имя `upstream_base_url`), `anthropic_auth` | Провайдер Anthropic Messages и способ передачи ключа |
| `openai_base_url`, `openai_api_prefix`, `openai_auth` | OpenAI-совместимый провайдер: Chat Completions, Responses, Completions, Embeddings |
| `gemini_base_url` | Google Gemini API |
| `code_index` | Распознавание закрытого кода по отпечаткам (`DET-20`): `path` (файл `aegis index build`), `threshold` (0,9), `min_tokens` (50; блок должен также содержать не меньше 12 разных идентификаторов), `actions` (классификация → `warn`, `drop_block`, `block_request`, `route:<маршрут>`), `default_action` (`warn`). Блок, похожий на репозиторий из индекса, обрабатывается действием его классификации; в аудит попадают имя репозитория, классификация и действие, кода нет. Файл перечитывается при изменении |
| `guard` | Устройства с Agent Guard (`AGG-05`, `AGG-03`): `devices` — список `{id, public_key}` (открытый ключ Ed25519 в hex; строку печатает `aegis-guard enroll` на машине), `max_age_secs` (300; от 30 до 28800) — срок токена. Запрос с действительным токеном (заголовок `X-Aegis-Guard` или часть ключа после `~`) получает вместо отказа подстановку персональных данных в **локальные** команды: пользователя спрашивает охранник на машине. Недействительный токен равен отсутствию охранника. Устройство видно в аудите (`guard`) и в метрике `aegis_guard_requests_total{state}`. Подробно: [GUARD.md](GUARD.md) |
| `oidc` | Вход по токену OpenID Connect рядом с виртуальными ключами (`IAM-04`): `issuer`, `audience`, один из `jwks_url` и `jwks_file`, `groups_claim` (`groups`), `principal_claim` (`sub`), `leeway_secs` (60), `refresh_secs` (300). Клиент передаёт JWT как ключ (`Authorization: Bearer`, `x-api-key`…); принципал получается `oidc:<значение утверждения>`, группы берутся из утверждения и работают в `routes`. Принимаются подписи RS256 и ES256 по ключам издателя; `none`, HMAC и токены без `exp` отклоняются. Ключи загружаются при запуске (без них gateway не стартует) и обновляются в фоне |
| `routes` | Статические маршруты (`RTE-01`): список `{name, protocol, base_url, api_prefix, auth, key_env, models, groups, reroute_only, model, context_tokens}`. Запрос идёт по первому маршруту своего семейства протоколов (`anthropic`, `openai`, `gemini`), у которого подходят шаблон модели (`*` — любая подстрока) и группа ключа; без совпадения — к провайдеру по умолчанию. Ключ маршрута берётся из переменной `key_env` (или `ИМЯ_FILE`), в конфигурации и в бандле его нет. Имя маршрута видят правила политики (`route:`) и аудит: так модель на своих серверах получает более мягкие правила, чем внешняя.

**Маршрут для закрытого кода** (`RTE-03`…`RTE-05`). Маршрут с `reroute_only: true` не выбирается по модели и группе: в него запрос попадает только по действию политики `route:<имя>` в `code_index.actions`. Если блок кода совпал с репозиторием классификации `closed`, а действие — `route:internal`, весь запрос уходит на маршрут `internal` (внутренняя модель). `model` у маршрута подменяет имя модели клиента, `context_tokens` — окно контекста модели (оценка по размеру запроса; запрос, который не помещается, не обрезается, а отклоняется). Маршрут должен быть того же семейства протоколов, что и запрос; иначе или если маршрута нет, запрос **отклоняется с 403**: закрытый код не уходит к исходному провайдеру из-за ошибки настройки. Разговор закрепляется за маршрутом на 8 часов (по соли, в памяти узла): следующие ходы без кода остаются на внутренней модели. Пользователь видит в начале ответа строку `[Aegis: запрос содержит закрытый код и направлен на внутренний маршрут «internal»]` (один раз на разговор) и `route=internal` в заголовке `X-Aegis-Summary`; в аудите — имя маршрута. Если ответ состоит только из вызова инструмента, строки в тексте нет, остаётся заголовок |
| `model_aliases` | Псевдонимы моделей: `{"claude-default": "claude-sonnet-..."}`. Клиент просит стабильное имя, провайдеру уходит настоящее; смена модели не требует правки клиентов. Работает для всех протоколов, у Gemini имя заменяется в пути |
| `tls` | TLS на основном порту: `cert_file`, `key_file` (PEM), необязательный `client_ca_file`: клиенты обязаны предъявить сертификат этого УЦ (mTLS). TLS 1.2 и 1.3, только HTTP/1.1. Файлы перечитываются раз в 30 секунд: обновлённый сертификат подхватывается без перезапуска, нечитаемый файл прежний сертификат не заменяет |
| `upstream_ca_file` | Закрепление УЦ провайдера (PEM): соединения с провайдерами доверяют только ему, публичные корни отключаются. Нужно для провайдера с частным УЦ или чтобы закрыть подмену сертификата |
| `otlp_endpoint` | Коллектор OpenTelemetry (OTLP/HTTP, JSON): `http://collector:4318`. На каждый запрос один трейс: корневой спан `aegis.request` и спаны стадий `parse`, `detect`, `transform`, `upstream`, `response`. Присоединяется к трейсу клиента, если пришёл `traceparent`. Атрибуты: маршрут, модель, клиент, решение, размер, число блоков, сущностей и отказов; значений и текстов нет. Заголовки коллектора (например, `Authorization`) — в `AEGIS_OTLP_HEADERS="k=v,k2=v2"`. Недоступный коллектор стоит спанов, не запросов |
| `detect_cache_mb`, `detect_budget_ms` | Память кэша обнаружения (1024 МБ, вытеснение LRU, на диск не пишется) и время на проверку одного блока (2000 мс). Блок, который не успели проверить, или проверка которого упала, заменяется на `[Aegis: блок не проверен и удалён]`, запрос не отклоняется; событие аудита получает `detector_faults`, метрика `aegis_detector_faults_total{kind}` растёт |
| `max_concurrent_requests` | Запросов одновременно (по умолчанию 1000, потоки считаются на всё время потока). Лишний запрос получает 503 с `Retry-After: 1` до чтения тела |
| `max_connections_per_ip` | Открытых соединений с одного адреса клиента; 0 (по умолчанию) — без ограничения. За балансировщиком у всех клиентов его адрес: ограничивайте там |
| `upstream_connect_timeout_secs`, `upstream_read_timeout_secs` | Ожидание соединения с провайдером (10) и молчания провайдера до ответа и между кусками потока (300). По истечении — 502 |
| `tenant` | Идентификатор тенанта |
| `bundle` | `source` (путь или URL), `cache_path`, `trusted_keys` (hex открытых ключей), `reload_seconds` (1–30) |
| `audit_path`, `audit_required`, `audit_queue` | Файл аудита JSONL (по умолчанию stdout), остановка трафика при переполнении очереди, размер очереди |
| `internal_zones`, `company_ranges`, `service_account_patterns`, `employees`, `terms`, `virtual_keys` | Те же настройки без бандла. С бандлом их задаёт политика |
| `detect_names`, `sweep_secrets` | Без бандла. `detect_names` (по умолчанию `true`): имена людей в свободном тексте по форме русских имён (`DET-30`), без каталога сотрудников. `sweep_secrets` (по умолчанию `true`): секрет, найденный в одном блоке запроса, маскируется и в других блоках с тем же текстом (`DET-35`). С бандлом: `detectors.names`, `detectors.sweep_secrets` |

Нужен хотя бы один провайдер. Подробности, адреса и примеры для DeepSeek, Qwen, Kimi, GLM, Azure, Ollama и других — в [PROVIDERS.md](PROVIDERS.md). Файл примера — [examples/gateway.json](../examples/gateway.json).

### Проверка конфигурации перед запуском

```
aegis-gateway check /etc/aegis/gateway.json
```

Команда ничего не запускает и не открывает порты надолго. Она проверяет: разбор конфигурации; ключи `K_t` и `K_audit` (длина, различие); провайдеров и их ключи; бандл (загрузка, подпись, срок: предупреждение, если до конца меньше 14 дней или взят кэш); запись в файл аудита; свободны ли порты. Выводит `ok`, `warn` или `FAIL` по каждому пункту, значения ключей и пароли в адресах не печатает. Код выхода 0, если нет `FAIL`, иначе 1. Подходит как шаг CI, `initContainer` или проверка перед перезапуском. Предупреждения: открытый наружу порт без TLS, служебный порт на всех интерфейсах.

### Индекс закрытого кода

```
export AEGIS_K_TENANT=...                       # тот же ключ тенанта, что у gateway
aegis index build --repo payments=/srv/git/payments:closed --repo core=/srv/git/core:secret -o code.idx
aegis index build --update --repo payments=/srv/git/payments:closed -o code.idx   # заменить один репозиторий
aegis index check code.idx some/file.go          # на что похож файл (код 1, если на репозиторий из индекса)
aegis index info code.idx
```

Индекс хранит отпечатки (хеши с ключом от последовательностей токенов, окно winnowing) и имена репозиториев, кода в нём нет, без ключа тенанта он не читается. Комментарии, пробелы, содержимое строк и чисел не влияют; имена сохраняются, поэтому массовое переименование идентификаторов снижает долю совпадения. Пересборку удобно запускать по расписанию или хуком Git после слияния: gateway подхватывает новый файл без перезапуска. Измерение (`aegis-bench code --closed <репозиторий> --negative <каталог>…`, `QA-10`): из «закрытого» репозитория вырезаются 3000 случайных фрагментов по 40 строк подряд, столько же вырезается из 500 других каталогов (другие версии того же крейта в отрицательный набор не входят: это тот же код). По умолчанию (порог 0,9, 50 токенов, 12 идентификаторов) на пяти репозиториях из `~/.cargo/registry`: ложных совпадений 0–0,03% (цель меньше 0,1%); полнота среди фрагментов, которые можно оценить, 97–100% у tokio, hyper, serde_json и clap_builder (цель не меньше 95%) и 77% у regex; ложные совпадения 0,03% только у hyper, у остальных четырёх ни одного из 3000. Не оцениваются фрагменты почти без кода (комментарии, таблицы чисел, строки): 19% у tokio, 4% у hyper, 15% у serde_json, 24% у clap_builder и 52% у regex. У regex файл `lib.rs` почти целиком проза внутри строк: фрагмент, начатый посреди многострочной строки или комментария, токенизируется иначе, чем целый файл, и совпадает хуже. Без условия на число разных идентификаторов таблицы данных (`unicode-normalization`) давали 1–2% ложных совпадений: после нормализации любые два списка чисел одинаковы. Короткие и шаблонные файлы похожи друг на друга сильнее, поэтому для опасных действий (`drop_block`, `block_request`, `route:`) не снижайте порог без измерения на своём коде.

### Проверка до внедрения

```
aegis scan path/to/repo --zone corp.local          # что будет замаскировано: файл, строка, тип, правило; значения не выводятся
aegis scan config.env --mask                       # тот же файл с подставленными псевдонимами
aegis scan . --policy policy.yaml --fail-on-findings   # в CI или pre-commit
```

Команда использует те же детекторы и правила, что и gateway, работает локально и без ключей.

## 3. Политика и бандл

Политика — YAML, строгая схема: неизвестное поле или значение — ошибка, а не молчаливый пропуск.

```yaml
version: 1
tenant: acme
zones: { internal: [corp.local, company.ru], company_ranges: ["10.50.0.0/16"] }
detectors:
  service_account_patterns: ['\bacme_[a-z]+_svc\b']
  names: true            # имена людей в свободном тексте по форме (DET-30), по умолчанию да
  sweep_secrets: true    # найденный секрет маскируется и в других блоках запроса (DET-35), по умолчанию да
  custom:
    - id: acme-token
      type: SECRET
      regex: 'ACME-TKN-([A-Z0-9]{12})'
      group: 1
      examples: { matches: ["ACME-TKN-AB12CD34EF56"], non_matches: ["ACME-TKN-x"] }
dictionary:
  employees: [{ first: Иван, last: Петров }]
  terms: [{ form: InternalPaymentSystem, type: SYSTEM }]
trifecta: { mode: enforce, allow_destinations: ["docs.python.org"] }
response:
  tool_secrets: deny          # секрет, который модель написала сама в аргументах вызова
  file_secrets: warn          # то же в содержимом записываемого файла (код с зашитым ключом)
  dangerous_commands: warn    # curl | sh, rm -rf /, authorized_keys, отключение песочницы
  dangerous_patterns: ['terraform\s+destroy']
defaults:
  ingress: { SECRET: mask, INFRA: mask, PII: mask, CORP: mask }
  secret_attributes: [kind, has]
  attachments: drop_block      # или block_request: запрос с изображением или документом отклоняется
  embeddings: mask             # или block_request: запросы эмбеддингов отклоняются
rules:
  - { id: R-020, when: { type: SECRET, kind: pem }, ingress: block_request }
  - { id: R-112, when: { sink: [shell_network, network] }, restore: { SECRET: deny, INFRA: internal_only } }
```

**Проверка того, что пишет модель (`response`).** Подстановка отвечает на вопрос, куда можно вернуть значение, которое Aegis замаскировал. Раздел `response` отвечает на другой: что модель пишет в вызовах сама. Значения `off`, `warn` (запись в аудит и метрику `aegis_warned_total{rule,sink}`, вызов проходит), `deny` (вызов заменяется объяснением).

| Ключ | Что проверяется | По умолчанию |
|---|---|---|
| `tool_secrets` | В аргументах вызова секрет, который детекторы узнают и который не наш псевдоним: модель воспроизвела ключ из обучающих данных или из места, которое Aegis не маскировал (правило `RSP-10`) | `deny` |
| `file_secrets` | То же в содержимом файла, который вызов записывает (правило `RSP-06`) | `warn` |
| `dangerous_commands` | Шелл-вызовы: загрузка и запуск (`D-01`), стирание системы или дома (`D-02`), `authorized_keys` (`D-03`), отключение песочницы агента или системы (`D-04`), `chmod 777 /` (`D-05`), fork-бомба (`D-06`) | `warn` |
| `dangerous_patterns` | Свои регулярные выражения для команд; номера `D-X1`, `D-X2`… | пусто |

Список опасных команд короткий: он про то, что почти никогда не нужно в обычной работе, и не заменяет песочницу клиента.

Порядок работы:

```
aegis keys generate --out signing.key                    # один раз; закрытый ключ хранить офлайн
aegis policy test policy.yaml tests.yaml                 # схема, примеры детекторов, тесты политики
aegis vkey issue --principal u:ivanov --file vkeys.json  # ключ печатается один раз, в файл идёт только хеш
aegis bundle build --policy policy.yaml --tests tests.yaml --key signing.key \
    --version 2026.10.07-1 --valid-days 90 --vkeys vkeys.json -o bundle.json
aegis bundle verify bundle.json --trusted <публичный ключ>
```

Сборка останавливается, если не проходят схема, примеры собственных детекторов или тесты политики. Бандл без тестов собирается только с явным `--no-tests`.

Gateway проверяет подпись, срок действия и политику, затем подменяет движок без перезапуска (не позже `reload_seconds` после публикации). Неверный бандл ничего не меняет, ошибка видна в `aegis_bundle_errors_total`. Последний действительный бандл копируется в `cache_path` и используется при перезапуске, если источник недоступен. Когда срок действия истёк, трафик останавливается (503), поэтому новый бандл надо публиковать заранее: метрика `aegis_bundle_expires_in_seconds`.

**Отзыв виртуального ключа:** `aegis vkey revoke --principal ... --file vkeys.json`, затем собрать и опубликовать новый бандл.

**Ротация ключей.** `K_t`: псевдонимы всех разговоров меняются сразу. Состояния нет, поэтому ничего не ломается: следующий запрос перемаскирует весь контекст новыми псевдонимами, но кэш промптов провайдера для идущих разговоров сбрасывается. Ротацию лучше делать в нерабочее время; ответ, который уже получен от провайдера в момент ротации, с новым ключом не подставится. `K_audit`: после замены записи аудита, сделанные до ротации, нельзя связать с новыми значениями (crypto-shredding); старый ключ после ротации уничтожается.

### Масштабирование и изоляция от интернета

**Масштабирование.** Узел не хранит состояния между запросами: любой запрос обрабатывает любой узел, поэтому достаточно запустить столько экземпляров, сколько нужно (в Helm — `replicaCount`). Кэш обнаружения локальный; чтобы его попадания были чаще, балансировщик может направлять запросы одного ключа на один узел (хеширование по заголовку `x-api-key`, `Authorization` или `x-goog-api-key`). Это оптимизация, а не требование: без неё всё работает, только кэш прогревается на каждом узле отдельно. Линейность роста до 16 узлов не измерена: стенд (`aegis-bench load`) измеряет один узел.

**Без доступа в интернет.** Gateway не обращается никуда, кроме провайдеров из конфигурации, источника бандла и коллектора трассировок, если он задан. Модели детекции, словари и шаблоны вшиты в бинарник (машинного обучения нет), зависимости собираются из `Cargo.lock`. В закрытой сети направьте `*_base_url` на локальные модели, `bundle.source` — на локальный путь или внутренний сервер, образ возьмите из внутреннего реестра.

## 4. Аудит и отчёты

Каждый запрос пишет событие JSONL: тип и вид сущностей, хеши (HMAC на `K_audit`), счётчики, решения по инструментам, сработавшие правила, состояние правила трёх условий. Значений и псевдонимов в аудите нет.

```
aegis report audit.jsonl                                  # сводка
aegis report audit.jsonl --since 2026-10-07T00:00:00Z     # период
aegis report audit.jsonl --conversation <хеш разговора>   # одна задача агента
```

## 5. Метрики (служебный порт, `/metrics`)

`aegis_requests_total{decision}` (`allow`, `rejected`, `overloaded`, `upstream_error`, `fail_closed`), `aegis_entities_total{class}`, `aegis_denied_total{rule,sink}`, `aegis_stage_ms{stage}` (parse, detect, transform), `aegis_detect_blocks_total{result}`, `aegis_pseudonym_collisions_total`, `aegis_bundle_applied_total`, `aegis_bundle_errors_total{reason}`, `aegis_bundle_info{version,signer}`, `aegis_bundle_expires_in_seconds`, `aegis_audit_overflow_total`.

Значений, путей и текста запросов в метриках нет.

## 6. Заголовки

| Заголовок | Направление | Назначение |
|---|---|---|
| `x-api-key`, `Authorization: Bearer`, `api-key`, `x-goog-api-key` или `?key=` | запрос | Виртуальный ключ (принимается любой из способов) |
| `X-Aegis-Conversation` | запрос, необязательный | Якорь соли псевдонимов |
| `X-Aegis-Request-Id`, `X-Aegis-Summary` | ответ | Идентификатор и счётчики по классам |

Заголовки `X-Aegis-*` и виртуальный ключ провайдеру не передаются.

## 7. Ограничения

- Только режим без состояния: `previous_response_id`, `item_reference`, `store: true`, Assistants, Files и Batches отклоняются.
- Серверные инструменты провайдера (web search, code execution, MCP connector, `enable_search` у Qwen, `$web_search` у Kimi, `retrieval` у GLM, `googleSearch` у Gemini) отключены.
- Сжатые тела запросов (`Content-Encoding`) отклоняются: 415.
- По умолчанию gateway слушает обычный HTTP: включите `tls` или завершайте TLS на балансировщике, основной порт не выставляйте наружу без шифрования. Служебный порт (`/metrics`, `/readyz`) всегда обычный HTTP и закрывается сетевой политикой.
- Провайдер по умолчанию один на семейство протоколов; для остальных моделей есть маршруты (`routes`).
- Изображения и PDF заменяются текстовым уведомлением.
- Cursor, Windsurf и встроенные подсказки GitHub Copilot ходят через серверы вендоров и в gateway не направляются; для них действует только блокировка на периметре (`deploy/egress`). Полный список клиентов — в [CLIENTS.md](CLIENTS.md).
- Образ контейнера собран и запущен, Helm-чарт отрендерен (`helm lint`, `helm template`), но в кластере манифесты не применялись: проверьте NetworkPolicy, пробы и egress у себя.
