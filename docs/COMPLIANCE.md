# Обработка данных в Aegis: описание для ИБ и юристов

## Что делает продукт

Aegis **псевдонимизирует** данные: заменяет значения обратимыми псевдонимами до отправки провайдеру и подставляет значения обратно в ответ. Это не обезличивание. Компания хранит ключ, по которому значения восстанавливаются, поэтому с точки зрения 152-ФЗ и GDPR такие данные остаются персональными. Aegis снижает риск и объём данных, уходящих провайдеру, но не освобождает от обязанностей оператора.

Формулировки «данные обезличены» и «персональные данные можно передавать за рубеж» в отношении Aegis использовать нельзя.

## Какие данные, где и сколько хранятся

| Что | Где | Срок |
|---|---|---|
| Тело запроса и ответа, реальные значения | Только в памяти процесса gateway | На время обработки запроса |
| Соответствие «псевдоним ↔ значение» | Только в памяти, строится заново из каждого запроса | На время обработки запроса |
| Бандл политики: словарь сотрудников (формы имён), хеши виртуальных ключей | Источник бандла и локальная копия `cache_path` (права 0600) | Пока бандл действует |
| Кэш детекции | Память; хранит позиции и типы, значений нет; не пишется на диск | До вытеснения или перезапуска |
| Аудит | Файл JSONL или stdout | Настраивается компанией |
| Метрики | Служебный порт | Определяется системой мониторинга |

Процесс запрещает core-дампы и отключает `dumpable`; в сервисном описании отключён swap (`MemorySwapMax=0`). Временных файлов с данными запросов нет.

## Что в аудите

Типы и виды сущностей, счётчики, решения, правила, идентификатор запроса, хеш разговора и хеши значений (HMAC-SHA256 на отдельном ключе аудита, 8 байт). Значений и псевдонимов в аудите нет. Хеши с ключом при строгом толковании могут считаться персональными данными, если ключ аудита доступен тому, кто может перебрать значения. Срок хранения аудита определяет компания. Aegis пишет в файл, который дописывается (`audit_path`), или в стандартный вывод; срок задаётся ротацией и удалением старых файлов средствами системы, например:

```
# /etc/logrotate.d/aegis: хранить 90 дней
/var/log/aegis/audit.jsonl {
    daily
    rotate 90
    compress
    copytruncate
    create 0600 aegis aegis
}
```

Ротация ключа аудита делает прежние записи несвязываемыми: это способ «забыть» хеши раньше срока (crypto-shredding).

## Что видит провайдер

Запрос, в котором значения заменены псевдонимами, структура кода и разговора, названия инструментов и их аргументы (также с псевдонимами). ### Настройки у провайдера

Псевдонимы не делают содержимое запроса безразличным: провайдер видит структуру кода, имена и логику. Поэтому настройки у провайдера остаются частью защиты:

- включите режим без хранения данных (zero data retention), если провайдер его предлагает по договору или настройкой организации;
- отключите обучение на данных клиента (для API это, как правило, значение по умолчанию, но проверьте условия вашего тарифа);
- выберите регион обработки, допустимый для вашего договора и регулятора; для моделей, размещённых за пределами вашей юрисдикции, учитывайте, что псевдонимизация не снимает требований к трансграничной передаче;
- для моделей на ваших серверах (vLLM, Ollama) сделайте маршрут `routes` и задайте для него отдельные правила политики: данные не покидают периметр;
- Aegis принудительно выставляет `store: false` для Responses API и отклоняет режимы, где состояние хранится у провайдера (`previous_response_id`, Assistants, Files).

Условия провайдеров меняются: сверяйте их с актуальными договором и документацией, здесь они не воспроизводятся.
