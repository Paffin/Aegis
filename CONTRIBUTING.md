# Как внести вклад

Спасибо, что хотите помочь. Aegis — инструмент безопасности: правки проходят строже, чем в обычном проекте, и это нормально.

## Что нужнее всего

1. **Настоящие провайдеры.** Клиенты проверены против подставных провайдеров (`scripts/clients.sh`); приём подписей thinking и `thoughtSignature` настоящими провайдерами не подтверждён. Нужны записи сессий без значений: заголовки, структура, события потока. Также нужны сценарии `scripts/client-*.sh` для клиентов, которых ещё нет (Roo и Kilo Code, Zed, Goose, Open WebUI) ([STATUS](docs/STATUS.md)).
2. **Ложные срабатывания и пропуски** на вашем коде. Запускайте `aegis scan`, присылайте тип, вид и контекст без самих значений.
3. **Обходы**: запрос, в котором значение доходит до провайдера. Если это уязвимость, пишите по [SECURITY.md](SECURITY.md), а не в публичный issue.
4. Провайдеры и клиенты, которых нет в [PROVIDERS](docs/PROVIDERS.md) и [CLIENTS](docs/CLIENTS.md).

## Сборка и проверки

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
scripts/smoke.sh        # сквозной тест на настоящих бинарниках
scripts/clients.sh      # настоящие клиенты против Aegis и подставного провайдера
scripts/trace.sh        # какие требования спецификации покрыты тестами
PROPTEST_CASES=40000 cargo test --release -p aegis-gateway --test fuzz   # долгий прогон фаззинга
```

На каждый push CI запускает быстрые проверки (fmt, clippy, тесты, трассировка, смоук, цепочка поставки, образ). Тяжёлые (гейты качества `aegis-bench`: полнота, ложные срабатывания, задержка, нагрузка; настоящие клиенты) идут на `main`, каждую ночь и вручную. Прогоны на настоящих моделях (`scripts/real_quality.py`, `scripts/agent_bench.py`, `scripts/client-real.sh`) стоят денег и в CI не входят: их делают перед выпуском и после правок детекторов. Pull request, который не проходит `clippy -D warnings`, не принимается; `unsafe` в рабочем пространстве запрещён.

## Правила

- **Тест вместе с изменением.** Ошибку сначала воспроизводит тест, потом она исправляется. Тест не должен подгоняться под код: ожидаемое значение берётся из спецификации или независимого источника.
- **Идентификаторы требований.** Тест называет требование, которое проверяет (`// REQ: RSP-01`); список — в [SPEC](docs/SPEC.md). `scripts/trace.sh` показывает пробелы.
- **Значения не попадают никуда, кроме ответа клиенту:** ни в журнал, ни в метрики, ни в ошибки, ни в аудит (инвариант INV-6). Канареечный тест (`tests/canary.rs`) это проверяет; новый путь вывода должен быть им покрыт.
- **Закрытый по умолчанию.** Незнакомое поле, тип блока, эндпоинт или инструмент отклоняется или проверяется, а не пропускается.
- **Честный статус.** Если не проверено на настоящем клиенте или провайдере, так и пишите в [STATUS](docs/STATUS.md) и в документации.
- **Стиль.** `rustfmt` по умолчанию; комментарии объясняют «почему» и ссылаются на требование, а не пересказывают код.

## Коммиты и pull request

Короткая тема в повелительном наклонении (`feat:`, `fix:`, `docs:`, `test:`), в теле — зачем. В описании PR: что изменено, как проверено, что не проверено. Шаблон подставляется автоматически.

## Выпуск версии

Журнал изменений пишется руками в `CHANGELOG.md`, раздел «Не выпущено»: что изменилось для пользователя. Выпуск:

1. Actions → `release-prepare` → Run workflow. Версия берётся из коммитов с прошлого тега (`feat:` повышает минорную, остальное патч, `!` или `BREAKING CHANGE` мажорную; пока `0.x` ломающее тоже минорная) или задаётся вручную. Скрипт `scripts/release.py` переносит «Не выпущено» под новую версию, меняет `Cargo.toml` и `Cargo.lock` и открывает pull request.
2. Слияние этого pull request и есть выпуск: `release-tag` ставит тег `vX.Y.Z` на `main` и запускает `release` (образ для amd64 и arm64, подпись, SBOM, бинарники, контрольные суммы, GitHub release).

В настройках репозитория должно быть включено Settings → Actions → General → «Allow GitHub Actions to create and approve pull requests».

## Ключи и данные

Не добавляйте в репозиторий настоящие ключи, дампы и данные клиентов, даже «старые». Тестовые значения должны быть синтетическими (`AKIAIOSFODNN7EXAMPLE`, `Jd8@2jd82k`).
