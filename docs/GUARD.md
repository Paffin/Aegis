# aegis-guard: проверка вызова на машине разработчика

Gateway видит то, что агент отправляет модели и что модель отвечает. Что агент собирается сделать с машиной, он не видит: прочитать `~/.ssh/id_ed25519`, дописать строку в `~/.bashrc`, выполнить `curl … | sh`. `aegis-guard` запускается хуком клиента перед каждым вызовом инструмента, читает вызов и отвечает: ничего против, спросить пользователя или отказать. Работает локально, без сети, за 5–10 мс вместе с запуском процесса.

Работает с клиентами, у которых есть хуки перед вызовом инструмента. Проверен настоящий Claude Code (`PreToolUse`, сценарий `scripts/client-claude-guard.sh`). Для клиентов без хуков остаются эвристики gateway.

## Что закрыто по умолчанию

| Правило | Что | Действие |
|---|---|---|
| `G-01` чтение | `~/.ssh`, `~/.aws`, `~/.kube`, `~/.config/gcloud`, `~/.azure`, `~/.gnupg`, `~/.docker/config.json`, `~/.netrc`, `~/.git-credentials`, `~/.npmrc`, `~/.pypirc`, `/etc/shadow`, `/etc/sudoers`, `id_rsa`, `id_ed25519`, `*.pem`, `*.p12` | спросить |
| `G-02` запись | то, что исполняется позже и открывает двери: `~/.bashrc`, `~/.zshrc`, `~/.profile`, `.git/hooks/**`, `/etc/**`, `LaunchAgents`, настройки самого клиента (`.claude/settings*.json`, `~/.codex/config.toml`), `~/.gitconfig` | спросить |
| `G-03` команды | загрузка и запуск (`curl … \| sh`), `rm -rf /`, `authorized_keys`, отключение песочницы (список из `RSP-10`) и свои шаблоны | спросить |
| `G-05` персональные данные | в команде почта, телефон, паспорт, СНИЛС, ИНН (с названием рядом) или номер карты (с проверкой Луна): гарантия для `AGG-03`, см. ниже | спросить (`commands.personal_data`: `ask`, `deny`, `allow`) |
| `G-04` узлы | команда или запрос, обращающиеся к узлу вне `network.allow_hosts` (если список задан) | спросить |

Пути приводятся к тому виду, который увидит файловая система: `~` и `$HOME` раскрываются, `..` сворачивается, символическая ссылка заменяется файлом, на который она указывает. В командах проверяются слова, похожие на пути (`cat ~/.ssh/id_rsa`, `< $HOME/.aws/credentials`); запись проверяется, когда в команде есть перенаправление `>` или программа вроде `tee`, `cp`, `mv`, `sed -i`. Адрес, который можно прочитать двумя способами (`http://a\@b`), в списке не состоит.

## Правила

`/etc/aegis/guard.yaml` (общие) или `~/.config/aegis/guard.yaml`; путь можно задать `--config` или `AEGIS_GUARD_CONFIG`. Файла нет — действуют встроенные правила. Файл есть, но не читается — хук отказывает всем вызовам: правила принадлежат администратору, и охранник без правил не охранник.

```yaml
version: 1
paths:
  deny_read: ["~/work/secrets/**"]          # к встроенным
  deny_write: ["**/Makefile.release"]
  allow: ["**/test-keys/**"]                # исключения из обоих списков
  action: ask                               # или deny
commands:
  deny: ['terraform\s+destroy']
  action: ask                               # или deny
  personal_data: ask                        # ask, deny или allow (G-05)
network:
  allow_hosts: ["*.corp.local", "github.com", "pypi.org"]
  action: ask
```

## Подключение к Claude Code

```
aegis-guard settings --aegis-guard /usr/local/bin/aegis-guard --config /etc/aegis/guard.yaml
```

Команда печатает фрагмент настроек: хук `PreToolUse` для всех инструментов и запреты `Read(~/.ssh/**)`, `Edit(~/.aws/**)` и подобные, чтобы отказывала и собственная система разрешений клиента. Чтобы пользователь не мог отключить хук, положите настройки в **управляемый файл настроек** машины (по документации Claude Code, `/etc/claude-code/managed-settings.json` на Linux и `/Library/Application Support/ClaudeCode/managed-settings.json` на macOS; пути и ключи, запрещающие пользовательские хуки, уточните для вашей версии клиента) и распространяйте его средствами управления конфигурацией.

Хук **никогда не отвечает `allow`**: ответ «разрешить» в Claude Code пропускает собственные запросы подтверждения у пользователя. Если у охранника нет возражений, он молчит, и клиент решает сам. Вызов, который не удалось разобрать, отклоняется.

Для других клиентов `--format generic` печатает `{"decision":"allow|ask|deny",…}` и завершается с кодом 2 при отказе.

## Доверие между gateway и охранником (`AGG-03`, `AGG-05`)

Без охранника gateway не отдаёт клиенту команды с настоящими персональными данными: локальная команда с почтой или телефоном заменяется отказом (`RST-09`). С охранником отказ можно заменить подтверждением пользователя: gateway подставляет значение в локальную команду, а охранник на машине перед запуском спрашивает пользователя (`G-05`). Чтобы gateway знал, что охранник действительно стоит на машине, из которой пришёл запрос, охранник присылает подписанный токен.

```
aegis-guard enroll --id laptop-ivan        # один раз на устройство: ключ в ~/.config/aegis/device.key (0600)
# печатает строку для администратора:  {"id": "laptop-ivan", "public_key": "…"}
```

Администратор добавляет её в конфигурацию gateway (`guard.devices`, [ADMIN](ADMIN.md)). Ключ устройства — пара Ed25519: на gateway и в бандле лежат только открытые ключи (в спецификации — HMAC; подпись делает то же без секрета каждого устройства на сервере). Токен действует 5 минут (`guard.max_age_secs`), подписывает идентификатор устройства, время и, если указан, разговор. Недействительный токен (просрочен, чужой ключ, неизвестное устройство) равен отсутствию охранника, запрос выполняется по правилам Этапа 1; в метриках `aegis_guard_requests_total{state="valid|invalid|absent"}`, в аудите — устройство.

Доставка токена. Токен живёт 5 минут, поэтому заголовок, заданный один раз при запуске клиента, не подходит. Два способа:

- **Вместе с ключом.** `aegis-guard credential --vk-file ~/.aegis/vk` печатает `<виртуальный ключ>~<токен>`; gateway отделяет токен по `~`. Для Claude Code это `apiKeyHelper` в настройках: клиент вызывает команду заново примерно раз в 5 минут.
- **Заголовком `X-Aegis-Guard`** (`aegis-guard token`) — для клиентов, которые умеют добавлять меняющийся заголовок. Для остальных администратор может увеличить `guard.max_age_secs` (до 8 часов), понимая, что украденный токен действует столько же.

Охранник отвечает на вопрос «спросить пользователя» тем, что Claude Code показывает запрос подтверждения (`ask`). Охранник не видит содержимое файлов, которые прочитает запущенная команда: он смотрит на текст команды.

## Что не сделано

- Токен привязан к устройству и времени, но не к процессу: тот, кто может читать `~/.config/aegis/device.key`, выпустит токен. Защищайте ключ как ключ SSH. Нет отзыва по сети: устройство убирают из `guard.devices` и перезапускают gateway.
- Привязка токена к разговору есть (`--conversation`), но Claude Code не знает разговора при вызове `apiKeyHelper`, поэтому обычно токен выдаётся без неё.
- Настройки песочницы клиента с сетевой политикой (`AGG-04`) в части самой песочницы: охранник проверяет узлы в командах, но не ограничивает процессы, которые клиент запускает сам.
- Охранник не видит, что делает запущенная программа: `python script.py` выполнит то, что в файле. Файловая проверка относится к вызову, а не к процессу.
- Проверка путей в командах приблизительна: переменные (`$X/.ssh`), подстановки и вложенные оболочки не раскрываются. Это второй замок, а не песочница.
